# AleksOS Launcher: контекст проекта

Общаться с владельцем на русском. Владелец не профессиональный программист, объяснять простыми словами.

## Цель
Android-лаунчер (рабочий стол), где **Android-приложения и Windows-программы живут рядом в одной сетке**.
Телефон остаётся обычным Android: звонки, Telegram и т. д. работают как всегда. Windows-программы
открываются по нажатию на иконку, как обычные приложения. Это НЕ виртуальная машина с Windows.

## Целевое устройство
Motorola Edge 40 Pro: Snapdragon 8 Gen 2 (SM8550), GPU Adreno 740, 12 ГБ ОЗУ, ARM64 (ARMv9), Android.
Adreno 7xx хорошо поддерживается драйвером Turnip (Mesa).

## Архитектура (принятые решения)
- **Лаунчер:** Kotlin, без AndroidX и сторонних библиотек, интерфейс строится в коде (без XML-разметки).
  Activity с категориями HOME + LAUNCHER.
- **Движок Windows (этап 2+):** стек как в Winlator: **Wine** (Windows API) + **Box64/Box86** (или FEX)
  для трансляции x86→ARM64 + **DXVK/VKD3D** (DirectX→Vulkan) + **Turnip** (Vulkan на Adreno),
  Linux-окружение через proot/chroot, X-сервер. Не писать с нуля: брать готовые компоненты, можно
  изучать/заимствовать код Winlator (GPL совместима с нашей лицензией GPL-3.0).
- Движок работает в foreground service (постоянное уведомление), держится «прогретым» для быстрого старта.
- **Каждая Windows-программа должна открываться как отдельная задача Android** (своё окно в «недавних»),
  а не в общем окне Windows, как в Winlator. Это ключевая и самая сложная фича.
- Точка входа в движок: `WindowsEngine.kt` (сейчас заглушка, `isAvailable = false`).

## Оформление (решения владельца)
- Рабочий стол «как Windows, но приспособленный под телефон». Расположение привычное (панель задач,
  меню «Пуск», окна с кнопками свернуть/развернуть/закрыть), но **внешний вид свой** (логотип «A»,
  свои цвета и иконки) — не копировать Windows, чтобы не было проблем с авторскими правами.
- Светлая тема: панель задач и «Пуск» — светлое «стекло»; окна — `AosDialog`, цвета в `Ui.kt`.
- Иконки на столе свободно перетаскиваются (`DesktopGrid.kt`), места хранятся в prefs.
- Всё своё AleksOS хранит в `/sdcard/AleksOS/` (Рабочий стол, Документы, Программы; позже «Диск C» для Wine).
  Рабочий стол = папка `AleksOS/Рабочий стол`: её файлы и папки видны на столе.
- Проводник «Этот телефон» — `ExplorerActivity` (своя задача в «недавних», окно можно уменьшить и
  двигать, свёрнутое показывается на панели задач). Нужен доступ «ко всем файлам».
- Самообновление из GitHub Releases (`Updater.kt`): versionCode = номер сборки Actions.
- «Загрузка как настоящая ОС» (`BootScreen.kt`): экран проверки железа + модули движка с кнопкой BIOS →
  заставка владельца (`res/drawable-nodpi/boot_splash.jpg`) → рабочий стол. По умолчанию только после
  включения телефона (не на каждое «Домой»). BIOS (`BiosView.kt`) — стиль UEFI, настройки движка в
  `SystemSettings.kt`; открывается и из «Пуска». BIOS-железа нет — это не ВМ, это настройки AleksOS.
- Движок (этап 2): основа — Winlator Cmod (MIT, github.com/coffincolors/winlator). Движок ~260 МБ,
  НЕ встраивать в APK: скачивать один раз в личную папку приложения (`files/engine`), запускать
  оттуда (из /sdcard запуск запрещён). `AleksOS` на /sdcard = диск D: для Windows-программ.
  Стандартные программы Wine (Блокнот, WordPad, cmd, Сапёр…) — в «Пуск → Стандартные».
- **targetSdk = 28** (как у Winlator): с targetSdk ≥ 29 SELinux запрещает исполнять файлы из папки
  приложения, а Wine/Box64 живут там. Из-за этого доступ к файлам — обычное разрешение
  READ/WRITE_EXTERNAL_STORAGE (не «доступ ко всем файлам»), окно рисуется под строкой состояния вручную.
- Пакет движка собирает `.github/workflows/engine.yml` (при изменении `engine/VERSION` или вручную) →
  Release `engine-N` (prerelease, не latest!): `aleksos-engine-N.tar.gz` + `engine-N.json` (размер, sha256).
  Установщик — `EngineManager.kt` (докачка, проверка sha256, свой распаковщик tar, сервис с уведомлением).
  Для проверки на эмуляторе адрес пакета подменяется файлом `files/engine-manifest-url.txt` (через `run-as`).
- Этап 2, шаг 2 (✅ 08.11.2026 Блокнот запустился на телефоне, build-15 + engine-2): код Winlator Cmod (ветка `main`, proot-версия!)
  перенесён в `com.winlator.*` (X-сервер, renderer, xconnector, sysvshm) + `app/src/main/cpp`
  (proot, libproot-loader как статическая программа без libc, libwinlator). Окно программы —
  `WineActivity` (своя задача), запуск: proot → box64 → `wine explorer /desktop=shell,WxH <cmd>`.
  `WineRuntime.kt`: диски (C: внутри, D: = /sdcard/AleksOS, Z: = /), env, журнал `files/engine-log.txt`.
  Пакет движка 2: готовый wineprefix в rootfs/home/xuser/.wine, imagefs_patches (libandroid-sysvshm),
  zink, chmod 755 всем файлам (в образе Winlator нет флагов исполнения). «Пуск → Стандартные Windows».
  На эмуляторе x86 proot стартует, но зависает (ptrace под трансляцией ARM) — проверять только на телефоне.
  Несколько программ: в Wine работает `winhandler.exe` (из Winlator), AleksOS шлёт ему команды по UDP
  (`com.winlator.winhandler.WinHandler`, пакет 64 байта, ShellExecuteA в cp1251; длинный путь → своя буква M:…Y:).
  Отдельный процесс Wine на вторую программу не работал.
  ✅ build-24: несколько программ одновременно работают (Блокнот + Сапёр + Редактор реестра).
  Установщики: VAG-COM 4.09 запускается (просит Wine Gecko — скачивается кнопкой «Установить»).
  Репак-установщики Inno Setup со скином (isskin.dll) падают: нет MFC42.DLL (в Wine её нет) — нужен будет
  установщик «компонентов Windows» (vcrun6 и т. п.). В интерфейсе движок называется «Windows Kernel» (решение владельца).
- Владелец смотрит работу через Remote Control с телефона: кнопки-вопросы и картинки там не видны,
  поэтому вопросы задавать обычным текстом.

## Этапы
1. ✅ Лаунчер: Android-приложения, поиск, плитка «Добавить .exe», Windows-программы с меткой WIN.
2. 🔶 Движок: Wine + Box64 — Блокнот работает, русский есть. Звук (ALSAServerComponent из Winlator → AAudio, реестр Audio=alsa)
   и DXVK/VKD3D (BIOS «DirectX»: DLL в system32/syswow64, оригиналы в windows/aleksos-wine-dlls, WINEDLLOVERRIDES=n,b)
   добавлены, на телефоне не проверены. Осталось: остальные настройки BIOS (память, ядра, версия Windows).
3. 🔶 Иконки из .exe (`ExeIcon.kt`), ярлыки .lnk (`LnkFile.kt`: LinkInfo и IDList), установка: setup.exe запускается
   как обычная программа, новые ярлыки из «Пуска» Wine (`InstalledPrograms.kt`) сами добавляются на стол.
   Не проверено на телефоне с настоящим установщиком.
4. ⬜ Отдельное окно Android на каждую Windows-программу.
5. ⬜ Интеграция: общие папки телефона как диск D:, общий буфер обмена, «открыть с помощью».
6. ⬜ USB/COM через OTG для диагностики авто.

## Программы, которые владелец хочет запускать
- Игры: GTA Vice City, GTA San Andreas, C&C Generals / Zero Hour, Red Alert, Казаки.
  Старые диски с защитой SecuROM/SafeDisc не работают; лучше GOG/Steam или no-CD версии.
- **Вася Диагност** (диагностика VAG). Нужен драйвер адаптера. План: своя прослойка `ftd2xx.dll`
  внутри Wine, которая передаёт команды в USB-адаптер через Android USB Host API (OTG).
  Реально для KKL-шнуров на FTDI; оригинальные HEX-V2/HEX-CAN с защищённым протоколом, скорее всего, нет.
- Программы с драйверами ядра и античитами в принципе не запустятся, не тратить на них время.

## Сборка и выпуск
- GitHub: `kalibert801-ctrl/Launcher-Android`, лицензия GPL-3.0.
- GitHub Actions (`.github/workflows/build.yml`) собирает APK на каждый push.
  Из ветки `main` APK публикуется в Releases (тег `build-N`), владелец качает его на телефон оттуда.
- Подпись: сборки на GitHub — release (не отладочная) с ключом `app/aleksos-release.keystore` (alias `aleksos`).
  Файл ключа зашифрован, пароль НЕ в репозитории: секрет GitHub `ALEKSOS_KEY_PASSWORD`, на ПК —
  `signing.properties` (в .gitignore). Публиковать пароль нельзя: иначе кто угодно подпишет поддельное
  обновление. Отладочный ключ `app/debug-signing.keystore` (пароль `android`) — только для локальных
  debug-сборок. Переход с отладочной подписи на release потребовал один раз удалить AleksOS.
  Причина перехода: Play Защита помечала отладочную сборку как «вредоносную» (запуск скачанных программ,
  самообновление, targetSdk 28); заодно убрано лишнее MANAGE_EXTERNAL_STORAGE.
- AGP 8.7.3, Kotlin 2.0.21, Gradle 8.14.3, compileSdk/targetSdk 35, minSdk 26, Java 17.
- Локальная сборка: `./gradlew assembleDebug` (нужен Android SDK / Android Studio).
- Папка проекта у владельца: `C:\Users\kalib\OneDrive\Desktop\Launcher-Android` (синхронизируется
  с OneDrive). Если начнутся проблемы со сборкой из-за блокировки файлов, предложить перенос вне OneDrive.
